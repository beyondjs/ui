# Shared interface writing

The package owns its default labels, accessibility names and recovery wording in English and Spanish. Products provide their domain names, causes, permissions, costs and consequences through the existing component options.

Name objects and tasks in headings. Use specific action verbs and one term per concept. Keep one idea per sentence and aim for 15 words; preserve necessary permissions, privacy, costs and recovery. Already-clear control names do not need extra words.

Distinguish an empty list, a search without matches, a refusal, an outage and an unconfirmed outcome. A failed response does not establish that a submitted action never arrived. A component describes its own state rather than promising that unrelated features work. Keep retry, retained-work and credential warnings explicit.

Offer contextual help when it resolves a real question. Keep dynamic values recognizable and preserve their full meaning rather than shortening them to meet a word count. The caller supplies domain-specific details; the package never invents them.

Maintain the paired catalogs and React/DOM defaults together. `npm test` checks public catalog parity and behavior. Installed browser checks validate affected journeys and text fit. The [review record](reviews/2026-10-20/interface-writing.md) distinguishes complete semantic coverage from selected runtime checks.

The optional Beyond Suite family reference owns the cross-product guidance in `branding/docs/writing.md`; this guide remains sufficient in a standalone package checkout.
