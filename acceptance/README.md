# Browser acceptance

`npm run acceptance` proves the packed package in a real browser, installed the way consumers install it.

## What a run does

1. `npm pack` into a temporary directory (the `prepack` build runs first) and prints the tarball's `sha512` integrity.
2. Prepares three consumers, each a temporary project whose path contains a space: `dom` (the plain DOM page), `react19` (the React page on React 19.3.0) and `react18` (the same page on React 18.3.1). Each installs the tarball and its React version with `npm install`, copies `fixtures/`, and bundles its pages with esbuild (the React consumers have two), which resolves `@beyond-js/ui`, `@beyond-js/ui/react` and both stylesheets through the package's `exports`. Nothing is read from this checkout's `src/`.
3. Serves each consumer from a static server on an ephemeral port and opens the browser: Google Chrome (Playwright's `chrome` channel, headless) by default, or Playwright's Firefox or WebKit build when `BEYOND_UI_BROWSER` names it (`chrome`, `firefox` or `webkit`). Every check opens its own browser context, so viewport, color scheme, reduced motion and touch never leak between checks.
4. Prints one line per check and consumer and a final count; exits with 1 when any check fails. Temporary projects, servers and the browser are removed on success and on failure.

`node acceptance/run.mjs "<text>"` runs only the checks whose consumer and name contain the text. `DEBUG=1` prints the full failure log. Run all three engines before a release:

```sh
npm run acceptance
BEYOND_UI_BROWSER=firefox npm run acceptance
BEYOND_UI_BROWSER=webkit npm run acceptance
```

Prerequisites: Node.js 22.21.1 or later, `npm install` in this repository, network or npm cache access for the consumers' React installs, and Google Chrome installed; for Firefox and WebKit, Playwright's builds for the pinned `playwright-core`, installed once with `npx playwright-core install firefox webkit`.

## Layout

- `run.mjs`: the run described above.
- `support/`: `consumer.mjs` (temporary consumer projects), `server.mjs` (static server), `browser.mjs` (the engine and small assertions), `listeners.mjs` (the listeners a page holds on `document` and `window`, recorded by a wrapper installed before any page script, so the teardown check measures them in every engine; in Chrome it also reads them through DevTools), `words.mjs` (visible copy per fixture language), `geometry.mjs` (the family bar and lockup measurements).
- `checks/`: the checks, grouped by area: `keyboard.mjs` (action menu, including one at the bottom of the viewport opening above its button without scrolling the page, dialog, busy confirmation, prompt), `picker.mjs` (including "Select all shown"), `notifications.mjs` (including the bounded "N+" count, "View all" closing the panel and, in React, closing it through the ref), `help.mjs` (help, tooltip, touch, focused form), `strict.mjs` (on React 19 and 18, a dialog mounted open and one opened by a button stay open under the external-store provider, keep what is typed, survive a store change and report only the person's closing) and `presentation.mjs` (reduced motion, themes, 320 px, 200 % zoom, a long dialog whose body scrolls, collection, sentence case and the 12 px label on tags, table headings, stacked rows' labels and menu headings, Rubik 300/400/500 from the package with latin-ext on demand, teardown, Spanish copy) and `family.mjs` (the family bar at 1440, 1024, 768, 390 and 320 px in both themes, the location's two long names sharing its width at 1024, 900 and 768 px, phones from 320 to 479 px with the family's long product names (`?product=`), touch and mouse, with and without a sidebar toggle (44 × 44 targets on touch, nothing overlapping, the location folded into the product menu with a toggle below 380 px), its keyboard, its menus inside the viewport, loading and unavailable states (the fallback addresses keeping the account link and Docs, nothing drawn after the product name outside an organization), stickiness, the lockup at every height from 18 to 40 px, `ProductNav`, `Unavailable` and a confirmation's consequence, measured by `support/geometry.mjs`) and `icons.mjs` (every catalog icon inside its 16, 20 or 24 px box with the 1.8 stroke, a labelled icon as an image, every icon-only control of the consumer and family pages named, showing only glyphs of the closed list and showing its name in a tooltip, with an open menu and dialog at 1280 and 390 px and the bar at 1440, 600, 390 and 320 px, surveyed by the tests' `support/names.mjs`, and `Preferences`: first paint from the device copy, a device choice kept across a reload, the account's values winning, and a page whose storage throws). Each check names the consumers it applies to.
- `fixtures/`: the physical consumer pages.
  - `dom/`: a plain JavaScript page that creates, mounts and destroys DOM components, in English (the package defaults), `family.html` (`family.js`), the family bar page, and `icons.html` (`icons.js`), the icon catalog at every size with `Preferences` (default light and English).
  - `brand/`: a copy of the family wordmark that the family pages measure the lockup against; see its [README](fixtures/brand/README.md). Every page imports Rubik from the installed `@beyond-js/ui/fonts.css` (esbuild emits its woff2 files beside the bundle).
  - `family.css`: the family pages' layout.
  - `react/`: a React page using `@beyond-js/ui/react` inside `StrictMode`, with Spanish copy passed through `labels` (`labels.js`), as a localized product does; and `store.html` (`store.jsx`), dialogs under `StrictMode` inside a provider that reads an external store with `useSyncExternalStore`, as products' language and session providers do; and `family.html` (`family.jsx`), the family bar page in Spanish with a sidebar toggle; and `icons.html` (`icons.jsx`), `Icon` at every size with `usePreferences`, whose copy follows the language in effect.
  - `data/`: the fictional sources both pages use: people for the picker (45, one disabled), requests for the collection, the clauses of a long dialog (`terms.js`, EN and ES), the family descriptors selected by `?family=` (`inside`, `outside`, `loading`, `unavailable`, and `long` and `nandu` with long names) and the product's own `fallback` selected by `?fallback=` (the names and addresses, or `bare`: the person and addresses outside an organization; `family.js`), and a notification adapter with modes selected by `?notices=` (`ready`, `empty`, `failed`, `unavailable`, `partial`, `bound`); `ready` answers as a product relay (`unavailable`), `partial` and `bound` as Beyond Projects (`sources`, and `more` at a bound of 2).
  - `page.css`: page layout only; component styles come from the package.

Each page exposes `window.fixture` so checks can switch a source into failure and call a complete teardown.

## What a pass proves and does not

A pass proves the installed artifact works in the engine it ran in (Chrome, Firefox or WebKit) for these fixture pages: exports and stylesheets resolve, keyboard, focus and Escape behave, busy dialogs hold, an action menu at the bottom of the viewport opens above its button and scrolls nothing, the picker keeps choices across pages and filters, notification states are stated (unreachable products by display name, a bounded count as "N+"), "View all" closes the panel, long dialogs scroll their body with title and actions in view, reduced motion, both themes, 320 px width, 200 % zoom (approximated as a 640 CSS px viewport at device scale 2) and touch targets, and that teardown releases the components' document listeners. It does not prove adoption by any product, Safari itself or mobile browsers (WebKit is Safari's engine, run by Playwright), screen reader output, or a real notification service: the adapters are fixtures.
