# Opening fixture

`index.html` and `ready.js` are a fictional application that names the family's `session` step on its waiting element, waits for one read and then draws a useful screen under a bar with the family lockup's parts (`.bui-family .bui-lockup-mark`, `.bui-lockup-name`), where the opening hands its identity over. The opening acceptance holds its module or read, fails them, takes the connection away or lets them finish; it tests the document presentation, never product integration. The wordmark is taken from the existing DOM acceptance fixture. With `?unnamed` its waiting element is a region that names no step and adds a note while it waits. `earlier.html` is the opening's markup before 0.21.0, served with this version's controller and stylesheet as a development server whose package changed under it would. With `?regions` (0.31.0) the page draws its structure at once after the session: a bar still loading (`data-state="loading"`, with the product menu's separator and chevron) and a region waiting for its first read (`/content`), which the opening covers until that read answers or its budget runs out; `?redraw` draws the bar's brand again while the identity lands on it. Since 0.25.0, `linked.js` stands in for `ready.js` as an entry that names an export its dependency (`parts.js`) lacks, so it never links, `thrown.js` as one that throws before drawing anything, and `revived.js` as one that throws and then moves anyway.
